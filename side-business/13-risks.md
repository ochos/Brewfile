# 13. リスク登録簿

> **免責**: 本ファイルの法務・税務に関する記述は一般情報であり、2026年8月時点の調査に基づく。**最終判断は税理士・専門家、および所轄の税務署に確認すること。** 制度は毎年変わる。

---

## 1. 事業を止めうるリスク（最優先）

| # | リスク | 影響 | 対策 | 期限 |
|---|---|---|---|---|
| R1 | **就業規則で副業が禁止されている** | 計画が前提から崩壊。最悪、懲戒 | **着手前に必ず確認**。許可制なら申請を通す。競業避止条項も併せて確認 | Day 1 |
| R2 | **住民税から勤務先に副業が伝わる** | 会社との関係悪化 | 確定申告時に住民税を「**自分で納付（普通徴収）**」に。ただし自治体によっては認められない場合があり、**完全な回避手段ではない** | 申告時 |
| R3 | **特商法により自宅住所・電話番号の公開義務** | 個人情報の流出 | **M1〜M2 はプラットフォーム（Zenn/BOOTH）に寄生**し、表記を代行させる。Stripe 直販に移るときはバーチャルオフィスを検討 | M3 移行時 |

**R1 は他のすべてに優先する。** 90日計画の Week 1 の最初のタスクに置いてある。

## 2. 税務リスク

| # | リスク | 内容 |
|---|---|---|
| T1 | **「20万円ルール」の誤解①** | 判定は「収入」ではなく **「所得（収入 − 経費）」** |
| T2 | **「20万円ルール」の誤解②** | 20万円ルールは**所得税のみ**。**住民税には20万円ルールがない**ため、所得が20万円以下でも住民税の申告は必要 |
| T3 | 帳簿の保存 | 事業所得として申告するには帳簿保存が要件（令和4年10月の通達改正）。**最初から売上・経費を記録しておく** |
| T4 | インボイス | B2C 中心なら**登録不要**（免税事業者のままでよい）。登録すると消費税の納税義務が発生する |
| T5 | 経費計上 | サーバー代・ドメイン代・**Claude Code 利用料**・書籍代は経費になりうる。**領収書を最初から保存する** |

### 記録しておくべきもの（Day 1 から）

- 売上: いつ・どこで・いくら（プラットフォームの管理画面のスクリーンショットで可）
- 経費: 領収書・クレジットカード明細（Claude Code の請求メールを専用フォルダに退避）

**月1,000円の段階では会計ソフトは不要。** スプレッドシート1枚で足りる。月10万円が見えてきたら会計ソフトを検討する。

## 3. 法務リスク

| # | リスク | 対策 |
|---|---|---|
| L1 | **ステマ規制（景表法、2023年10月〜）** | アフィリエイトリンクを貼る記事には**必ず PR 表記**。自分の商品を売る場合は自分が事業者になる |
| L2 | **Qiita の規約違反** | Qiita は広告・宣伝・商用勧誘（SEO・アフィ目的投稿を含む）を明示的に禁止。**記事本体が知識共有として成立していること**が必須。宣伝目的の投稿はアカウント停止のリスク |
| L3 | **Google のスパムポリシー** | AI で量産した薄い記事は scaled content abuse の対象。**1本ずつ手をかけて書く** |
| L4 | **生成AIコードの権利** | Claude Code の出力の商用利用可否は利用規約で確認済みであること。他者のコードをそのまま出力していないかは、**特徴的な文字列で検索して確認**する習慣を付ける |
| L5 | **利用規約・プライバシーポリシー** | Chrome 拡張を出す時点で必要。特に拡張が収集するデータの明示は Web Store の審査項目 |
| L6 | **外部送信規律（電気通信事業法）** | 解析ツールを入れるならプライバシーポリシーに公表セクションを設ける。**Cloudflare Web Analytics を使えば同意バナー自体が不要**になり、この問題を回避できる |

## 4. 事業リスク

| # | リスク | 確率 | 対策 |
|---|---|---|---|
| B1 | **1冊も売れない** | **高** | 90日計画の Day 60 判定で「告知量」を先に疑う。商品を作り直す前に、告知を3倍にする |
| B2 | **記事が読まれない** | 中 | ネタが狭すぎる／既出すぎるのが典型。Week 2 の300PVチェックで早期に検知 |
| B3 | **Chrome 拡張が使われない** | **高** | 1本目で諦めないこと。実例の開発者は17〜20本作っている。**打席数で勝つモデル**だと最初から理解しておく |
| B4 | **Manifest 仕様変更で作り直し** | 中 | 拡張のコード量を小さく保つ。凝った実装をしない |
| B5 | **本業の繁忙期で計画が止まる** | **高** | タスクを削らず期間を延ばす。ただし週次レビューだけは15分でも続ける |
| B6 | **モチベーションの枯渇** | **高** | これが最大の撤退要因。「公開したものの数」を指標に入れているのはこのため（自分でコントロールできる唯一の数字） |
| B7 | **Claude Code の習熟がボトルネックになる** | 中 | 本人申告（2026-08-30）: 「他のチャットAIと異なり独自ルールが多くてとっつきづらい。まだ勉強中」。**M1（執筆）はClaude Code依存が低いため直撃しない。**M2（Chrome拡張）までの3ヶ月を習熟期間として使う設計になっている。M2着手時点でまだ厳しければ、M2を「拡張」から「デジタル商品の追加」に差し替えて時間を稼ぐ |

## 5. セキュリティリスク（Chrome 拡張・Web サービス）

技術調査（04）が「**最頻出は認可漏れ**」と指摘している。認証はあるが所有者チェックがない、という形。

Claude Code に実装させたあと、以下を必ず自分で確認する:

- [ ] **シークレットがコードに直書きされていないか**（API キー、トークン）
- [ ] **他人のデータを ID 指定で読めてしまわないか**（認可漏れ）
- [ ] 拡張の権限要求が最小か（`<all_urls>` を安易に要求していないか）
- [ ] ユーザー入力をそのまま SQL / HTML に埋めていないか
- [ ] レート制限があるか

**「少し書ける」水準でこれを全部見るのは難しい。** Claude Code の `/security-review` を公開前に必ず1回走らせる、というルールにしておく。

## 6. 情報の信頼性リスク（この計画自体のリスク）

本プロジェクトの調査は、**セッションのネットワーク制限により一次情報の直接取得ができなかった**。以下は特に検証が必要:

| 項目 | 状態 | 確認先 |
|---|---|---|
| Zenn / note / BOOTH の正確な手数料 | 二次情報のみ | 各公式ヘルプ |
| Cloudflare / Stripe / Resend の無料枠と価格 | 検索スニペット由来 | 各公式料金ページ |
| 「Zenn Books で 2,000PV → 5冊」の転換率 | **n=1 の単一事例** | 外挿の根拠としては弱い |
| アフィリエイト市場調査の分布 | スニペット由来 | 日本アフィリエイト協議会の原文 |
| 各種「2026年最新」系の記事 | **AI生成の疑いが強いものが多数** | 採用していないが、再調査時は注意 |

**金を払う判断（サービス契約、有料プラン加入）をする前に、必ず公式サイトで数字を確認すること。**

各調査ファイルの末尾に「未確認・要再確認リスト」があるので、そちらも参照。
