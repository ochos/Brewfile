# 公開スケジュール

前提: Zenn は**24時間で5本以上の投稿でブロック**され、**待つだけでは復帰せず新しいコミットが必要**（`research/05-zenn-publishing.md`）。
→ **記事は1日1本まで。余裕をみて3日あける。**

---

## 順序の考え方

**本を先に出す。** 記事④（型番）は集客力が最も強いが、**本が無い状態で人を集めても売上にならない**。

```
記事② → 記事③ → 【本①】 → 記事④ → Qiita クロス投稿
  集客の土台        商品          最強の集客       到達の上乗せ
```

記事②③は入門レベルで、**本①の第2章・第3章の話題**。読んだ人がそのまま本の読者になる。
記事④は検索から来る人向けで、**本①の第6章の話題**。本がある状態でぶつけたい。

---

## 前提作業（公開の前に必ず）

| # | 作業 | 所要 | 誰が |
|---|---|---|---|
| 1 | **ブラウザで5項目確認**（→ `publish/SETUP.md` STEP 7） | 21分 | **本人** |
| | └ **有料販売に著者の住所開示が必要か** ← これ次第で計画が変わる | | |
| 2 | **Zenn 用の Private リポジトリ作成** | 5分 | 本人 |
| 3 | Zenn と GitHub を連携 | 10分 | 本人 |
| 4 | 本文中の `<!-- ▼ 筆者確認 ▼ -->` を全削除 | 5分 | どちらでも |
| 5 | `assemble.py --check` が通ることを確認 | 1分 | どちらでも |

> **1 が最優先。** 住所開示が必要だった場合、Zenn での販売そのものを見直す（BOOTH 等へ変更）。
> **それが確定するまで、2〜5 に進んでも手戻りになる。**

## Day 0 — 記事② 公開

- [ ] `drafts/articles/02-what-is-multiplexed.md` の `published` を `true` に
- [ ] Zenn リポジトリの `articles/` に配置して push
- [ ] `/dashboard/deploys` で**公開されたことを確認**（push 成功 ≠ 公開成功）
- [ ] X で告知（テンプレ: `publish/templates/x-announce.md`。**リンクは1リプ目**）
- [ ] **1週間後の再告知を、この日に予約投稿してしまう**

## Day 3 — 記事③ 公開

- [ ] 同上の手順
- [ ] 記事②の末尾から記事③へリンクを追加（相互に繋ぐ）

## Day 5〜7 — 本① 公開 ★

- [ ] `assemble.py /path/to/zenn-content` を実行
- [ ] `cover.png` を `books/dwdm-intro/` に配置
- [ ] **`published: false` のまま push** し、Zenn 上で表示を確認
  - [ ] 6章すべて表示されているか（config の `chapters` 漏れは**エラーにならない**）
  - [ ] 無料公開章が第1章・第3章になっているか
  - [ ] 価格が 500円になっているか
  - [ ] 表紙が出ているか
- [ ] 問題なければ `published: true` にして push
- [ ] **記事②③の末尾に、本への導線を追記**（現在はコメントアウトしてある）
- [ ] X で告知（本公開用テンプレ）

## Day 8〜10 — 記事④ 公開

- [ ] `drafts/articles/04-pluggable-naming.md` を公開
- [ ] 末尾の本への導線を有効化
- [ ] X で告知

## Day 14 以降 — Qiita へクロス投稿

- [ ] **Zenn 公開から7日以上あける**
- [ ] **有料本へのリンクを一切置かない**（Qiita は宣伝を規約で禁止）
- [ ] 冒頭に転載元（Zenn）へのリンクを明記
