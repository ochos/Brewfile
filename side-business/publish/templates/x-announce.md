# X 告知投稿テンプレ — 完成形（コピペ用）

設計理由: [`../../research/06-launch-ops.md` §1-4](../../research/06-launch-ops.md)

## 使い方（毎回同じ・所要時間 5分）

1. 該当するテンプレの `text` ブロックをコピーし、【】部分だけ差し替える
2. **本文にURLを入れない**。そのまま投稿する
3. 投稿できたら、**自分のその投稿にリプライ**して、URLを貼る（1リプ目テンプレは各セクションの下）
4. Bの再告知は、**Aを投稿した直後に予約投稿で7日後にセットしてしまう**（+3分。これで1週間後の作業がゼロになる）

> **文字数の制約**: 無料アカウントの上限は280（日本語1文字＝2でカウント → **全角140字**）。
> 下のテンプレはすべて上限内で作ってある。**行を足すと超える。** 足したいときは他を削る。

---

# A. 記事公開時（当日）

```text
光伝送の担当になった1〜3年目向けに、「OSNRが足りない」と言われたら何を確認するか書きました。

・OSNRは何と何の比か
・設計値と実測値がズレる理由
・確認する順番

日本語でまとまった資料がない領域なので、自分が詰まった順に並べています。

リンクはリプ欄に。
```

**差し替え箇所（記事が変わったとき）**:

| 行 | 差し替えるもの |
|---|---|
| 1行目 | 「〈読者〉向けに、〈記事が答える問い〉を書きました」の形は変えない |
| 箇条書き | **3行。**記事の見出しから3つ選ぶ。4行以上にしない |
| 下から2行目 | 「なぜ自分が書けるのか」を1行。毎回同じでよい |
| 最終行 | 変えない |

### 1リプ目（Aの直後・必ず自分の投稿へのリプライとして）

```text
記事はこちらです
https://zenn.dev/【ユーザー名】/articles/【記事のslug】
```

# B. 1週間後の再告知（**Aと同時に予約投稿しておく**）

```text
先週書いた「OSNRが足りないと言われたら何を確認するか」、思ったより読まれています。

反応が多かったのは「設計値と実測値がズレる理由」でした。配属直後に一度は必ず詰まるところだと思います。

同じところで止まっている方に届けば。リンクはリプ欄に。
```

**注意**: 「思ったより読まれています」は**実際に読まれている場合のみ**使う。PVが伸びていないときは下の差し替え版を使う。

### B'. 反応が薄かったとき用（差し替え版）

```text
先週書いた「OSNRが足りないと言われたら何を確認するか」を、もう一度だけ置いておきます。

社内に体系的な資料がなく、ベンダー資料は分厚すぎて読めない。配属直後の自分がまさにその状態でした。

同じ状況の方に。リンクはリプ欄に。
```

### 1リプ目

```text
記事はこちらです
https://zenn.dev/【ユーザー名】/articles/【記事のslug】
```

# C. 本（Zenn Books）公開時

```text
光伝送（DWDM）の実務を、配属1〜3年目向けにまとめた本を出しました。500円です。

・OSNRと光レベルの読み方
・スパンロスと分散の考え方
・開通試験で見る項目
・アラームからの切り分け

社内に資料がなく、ベンダー資料は分厚すぎる人向けです。

目次と第1章は無料。リンクはリプ欄に。
```

**差し替え箇所**:

| 行 | 差し替えるもの |
|---|---|
| 1行目 | 「〈領域〉を、〈読者〉向けにまとめた本を出しました。〈価格〉円です。」 |
| 箇条書き | **4行。**章タイトルではなく「読者が得るもの」で書く |
| 下から2行目 | 読者の状況を1文で名指し。変えなくてよい |
| 最終行 | 「無料で読める範囲がある」ことを必ず書く。**ここが購入率に直結する** |

### 1リプ目

```text
本はこちらです。目次と第1章は無料で読めます
https://zenn.dev/【ユーザー名】/books/【本のslug】
```

### 2リプ目（**任意**。無料記事も読んでほしいとき）

```text
関連する無料記事はこちら
https://zenn.dev/【ユーザー名】/articles/【記事のslug】
```

> **⚠️ 本の告知は1回だけ。** 同じ本を繰り返し告知しない。次に本の名前を出してよいのは、関連記事を公開するとき（→ D）。

# D. 関連記事公開時（過去記事・本への導線を兼ねる）

```text
スパンロスの求め方と、実測が合わないときに疑う順番を書きました。

・スパンロスは何から計算するか
・実測とズレる典型的な3つの原因
・設計でどれだけ余裕を見るか

前に書いたOSNRの記事の続きにあたる内容です。リンクはリプ欄に。
```

### 1リプ目（新記事 → 前記事の順。**本のリンクはここに置かない**）

```text
今回の記事
https://zenn.dev/【ユーザー名】/articles/【新記事のslug】

前提にしている記事
https://zenn.dev/【ユーザー名】/articles/【前記事のslug】
```

### 2リプ目（**本を出したあとのみ**。1リプ目と分ける）

```text
この2本をまとめて体系的に読める本も出しています（500円 / 第1章まで無料）
https://zenn.dev/【ユーザー名】/books/【本のslug】
```

> **なぜリプを分けるか**: 1リプ目に販売リンクを混ぜると「記事は宣伝の入口だった」と読まれる。
> 分けておけば、無料記事だけ読む人はそこで止まれる。**止まれる設計にしておくことが、次に読まれる条件。**

# 共通ルール（毎回チェック）

- [ ] 本文にURLが入っていない
- [ ] ハッシュタグは0〜2個（`#光伝送` `#DWDM` 以外は使わない）
- [ ] 会社名（現職・前職）が入っていない
- [ ] スクリーンショット・実機写真を添付していない
- [ ] 「バズ」「拡散希望」「RTお願いします」が入っていない
- [ ] 全角140字を超えていない（超えたら行を削る。分割しない）
