# 記事公開 チェックリスト（時系列）

対象: Zenn の無料記事1本
**合計 約65分**（うち本人レビュー25分 / 残りは機械作業）
設計理由: [`../../research/06-launch-ops.md` §2](../../research/06-launch-ops.md)

公開日時は **火・水・木のいずれか 8:00** に固定する。迷わないための決め打ち。

## ■ 公開1時間前（前夜でよい） — 25分

**ここが本人レビューの本体。ここでしか見ない項目を先に置く。**

### 1. 守秘義務チェック（8分）★最優先

- [ ] 現職・前職の**社名**が本文・図・URLに入っていない
- [ ] **顧客名・拠点名・区間名・NE名**が入っていない
- [ ] **実網の構成が推測できる数値**（区間長・波長数・実際のロス値）を使っていない → 教科書的な例示値に置き換えたか
- [ ] **スクリーンショットを使っていない**（図はすべて自分で描き直したか）
- [ ] 特定の障害事例が**日時・区間の粒度で**書かれていない

> **1つでも引っかかったら公開しない。** 直してから翌週に回す。**この項目だけは「まあいいか」を許さない。**

### 2. タイトルの最終確認（5分）

- [ ] タイトルに **入口①製品名／②アラーム文言／③現場語彙 のいずれか1つ**が入っている（→ [`keywords-dwdm.md`](keywords-dwdm.md)）
- [ ] 2つ以上入っていない（欲張ると弱くなる）
- [ ] **ベンダー型番がタイトルの主語になっていない**（`Ciena 6500 完全ガイド` → ✗ / `〜のときに確認したこと（Ciena 6500の例）` → ○）
- [ ] 40字以内
- [ ] 「〇〇とは」ではなく、**困っている状態**を書いている

### 3. 冒頭3行の確認（3分）

- [ ] 1行目で**読者を名指し**している（例:「光伝送の担当になったが社内に資料がない1〜3年目向け」）
- [ ] TL;DR（結論3行）が冒頭にある

### 4. リンクの確認（3分）

- [ ] 記事内のリンクを全部クリックして、404がない
- [ ] 本を出している場合、**本へのリンクは末尾に1つだけ**
- [ ] 本をまだ出していない場合、**販売の予告を書いていない**（「近日公開」は書かない）

### 5. 公開設定（6分）

- [ ] 公開日時を **火・水・木 8:00** に設定（Zennの予約公開 or 当日手動）
- [ ] トピック（タグ）を3〜5個設定（`ネットワーク` `光通信` `インフラ` など）
- [ ] 絵文字アイコンを設定

> **誤字脱字は直さない。** 公開後にいつでも直せる。ここで時間を使うと公開が遅れる。

## ■ 公開当日 — 25分

### 6. 公開と表示確認（5分）

- [ ] 公開する
- [ ] **スマートフォンで開いて**、表・コードブロック・図が崩れていないか見る（PCだけで確認しない）

### 7. X で告知（10分）

- [ ] [`x-announce.md`](x-announce.md) §A をコピーし、【】を差し替えて投稿（**本文にURLを入れない**）
- [ ] 投稿できたら、**自分のその投稿にリプライ**して記事URLを貼る
- [ ] 全角140字を超えていないか確認してから投稿する

### 8. 1週間後の再告知を「今」予約する（5分）★これで翌週の作業が消える

- [ ] [`x-announce.md`](x-announce.md) §B（または反応が読めないなら §B'）をコピー
- [ ] X の予約投稿で **7日後の21:00** にセット
- [ ] 予約一覧に入っていることを目視確認

### 9. 過去記事からの内部リンク（5分）

- [ ] 過去に公開した記事のうち**最も関連が近い1本**を開き、末尾に新記事へのリンクを追記する

> **なぜGoogle Search Consoleを使わないか**: Zennは自分のドメインではないため、URL検査もインデックス登録リクエストも使えない。
> **代わりに内部リンクを増やすのが、この構成で唯一できるクロール対策。**
