# Qiita クロス投稿 チェックリスト＋定型文（コピペ用）

設計理由と規約の引用: [`../../research/06-launch-ops.md` §3](../../research/06-launch-ops.md)
所要時間: **90〜120分**（書き直しを含む。単純コピペは禁止なので短縮できない）

---

## 大前提（この3つを外すと規約違反になる）

### 1. Qiitaに有料本への直接リンクを置かない

Qiitaの利用規約は「広告・宣伝や商用を目的とした勧誘と客観的に認められる行為（検索サイト最適化またはアフィリエイトを目的とする投稿行為を含むがこれに限られない）」を禁止している。
→ [Qiita 利用規約](https://qiita.com/terms)

コミュニティガイドラインは「宣伝・販売を主目的とした、エンジニアにとって有益でない投稿は…投稿しないでください」としつつ、「自身や自社の技術を主に解説する記事は、宣伝・販売にはあたりません」としている。
→ [Qiita コミュニティガイドライン](https://help.qiita.com/ja/articles/qiita-community-guideline)

> **本プロジェクトの固定ルール**:
> 導線は `Qiita記事（技術解説として完結） → Zennの無料記事 → Zennの本` の3段にする。
> **Qiitaには無料記事へのリンクしか置かない。** グレーゾーンに一切踏み込まないことで、判断コストをゼロにする。

### 2. コピペ転載をしない

ZennもQiitaも**ユーザー定義の canonical URL に対応していない**（Zennはfrontmatterに書いても公開HTMLに反映されない）。
→ [Zennのcanonicalは公開HTMLに効かない](https://zenn.dev/zhener/articles/zenn-canonical-crosspost-seo) / [ZennとQiitaに同じ記事を投稿してcanonicalを壊さない3つのルール](https://qiita.com/Cosoado/items/4e7353d400340583c007)

→ **技術的に解決できない。内容を変えるしかない。**

### 3. 7日以上あける

原本（Zenn）を先にGoogleにインデックスさせる。

## 手順

### Step 1: 出すかどうかを判定する（2分）

[`checklist-article-launch.md`](checklist-article-launch.md) §12 の表で判定済みのはず。まだなら:

| 条件 | 判定 |
|---|---|
| Zenn原本の1週間PVが100未満 | 出す |
| 原本が特定の1トラブルに絞れている | 出す |
| 原本が体系的な解説で、PVが100以上 | 出さない |

### Step 2: 切り口を変える（60〜90分）

**同じテーマで、役割を分ける。**

| | Zenn（原本） | Qiita（別記事） |
|---|---|---|
| 役割 | **体系的な解説** | **特定の1トラブルの手順** |
| 例 | 「OSNRが足りないと言われたら何を確認するか」 | 「Pre-FEC Signal Degradeが出たときの切り分け手順」 |
| 構成 | 概念 → 理由 → 確認項目 → 背景 | 症状 → 手順1〜5 → 結果の読み方 |
| 分量 | 3,000〜5,000字 | 1,500〜2,500字 |

- [ ] 本文の一致率を**50%未満**にする（見出しから作り直すのが早い）
- [ ] Qiita版は**手順が主役**（番号付きリスト中心）
- [ ] Zenn版にしか書いていない「背景・理由」の部分は、Qiita版に持ち込まない（そこが原本を読む理由になる）

### Step 3: 冒頭に原本への参照を置く（3分）

**以下をそのままコピーして、Qiita記事の冒頭に貼る。**

```markdown
> この記事は、[Zennに公開した「【原本のタイトル】」](【原本のURL】)の内容を、
> 「【Qiita版で絞ったテーマ】」に絞って書き直したものです。
> 概念の整理や背景については原本のほうが詳しいので、あわせて参照してください。
```

**記入例**:

```markdown
> この記事は、[Zennに公開した「OSNRが足りないと言われたときに確認すること」](https://zenn.dev/xxx/articles/yyy)の内容を、
> 「Pre-FEC Signal Degrade が出たときの切り分け」に絞って書き直したものです。
> 概念の整理や背景については原本のほうが詳しいので、あわせて参照してください。
```

### Step 4: 末尾のリンク（3分）

**以下をそのままコピーして、Qiita記事の末尾に貼る。**

```markdown
---

同じ領域で、以下の記事も書いています。

- [【関連するZenn記事のタイトル1】](【URL1】)
- [【関連するZenn記事のタイトル2】](【URL2】)
```

- [ ] **有料本のURLをここに書かない**
- [ ] リンクは2本まで
- [ ] 「よければ本もどうぞ」等の販売を示唆する文言を書かない

### Step 5: 公開前チェック（5分）

- [ ] 原本の公開から**7日以上**経っている
- [ ] 本文の一致率が50%未満
- [ ] 冒頭に原本への参照がある
- [ ] **有料本へのリンクが1つもない**
- [ ] アフィリエイトリンクが1つもない
- [ ] 守秘義務チェック（[`checklist-article-launch.md`](checklist-article-launch.md) §1）を通した
- [ ] タグを3〜5個（`ネットワーク` `光通信` `インフラ` など）

### Step 6: 公開後（5分）

- [ ] Xでの告知は**しない**（Qiita版は検索流入専用。同じ内容を2回告知すると読者を消耗させる）
- [ ] Zenn原本の末尾に「この記事の一部を、Qiitaで手順に絞って書きました」と1行だけ追記（相互リンク）

## やってはいけないこと（Qiita）

| ❌ | なぜ |
|---|---|
| Zenn記事のコピペをそのまま投稿 | 重複コンテンツで**両方の順位が下がる**。canonicalで回避できない |
| 有料本の販売ページへのリンク | 利用規約（広告・宣伝・商用勧誘）に触れうる |
| アフィリエイトリンク | 利用規約で明示的に禁止 |
| 本の紹介・目次が主目的の記事 | コミュニティガイドライン違反 |
| 検索流入目的の薄い記事の量産 | 利用規約（検索サイト最適化を目的とする投稿行為） |
| 同じ内容を毎回両方に出す | 記事数は増えるが検索評価は下がる。**Qiita版は選んで出す** |

---

## はてなブックマークについて（何もしない）

- **セルフブックマークをしない**（1回もしない）
- **知人に「ブクマして」と頼まない**（複数アカウントでの同一URLブックマークは明確にスパム行為）
- 付いたら喜ぶだけ。**集客施策としてカウントしない**

根拠: [はてなブックマークにおけるスパム行為の考え方および対応について](https://b.hatena.ne.jp/help/entry/spam) / [はてなブックマークガイドライン](https://b.hatena.ne.jp/guide/guideline)

**例外的にやってよいこと**: 自分が読んで良かった**他人の記事**を、コメント付きで普通にブックマークする。これは通常利用。ただし週次ルーティンには入れない。
