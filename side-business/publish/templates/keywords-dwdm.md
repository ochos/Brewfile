## この領域の戦い方（前提）

**検索ボリュームで選ばない。** この領域の語は月間検索数が測定限界以下（10未満）のものが大半で、キーワードツールでは何も見えない。

代わりに次の基準で選ぶ:

1. **ベンダーの公式ドキュメントがログイン必須で、検索結果に本文が出ないもの**（例: my.ciena.com 配下）
2. **日本語の公開記事が1本も存在しないもの**（実際に検索して確認する。3分）
3. **現場の人間が、困った瞬間にそのまま打ち込む言葉**

**1と2が両方成立していれば、検索数が月10でも1位が取れる。** そして月1,000円に必要な有効閲覧は200〜400回（[`03`](../../research/03-marketing-acquisition.md)）なので、これで足りる。

## 入口① 製品名・型番（指名検索・競合ほぼゼロ）

| クエリ例 | 想定検索者 | 記事側の対応 |
|---|---|---|
| `Ciena 6500 とは` / `Ciena 6500 設定` | 配属直後で機材名しか手がかりがない | 型番と一般名（ROADM / トランスポンダ）を**同じ段落内で併記** |
| `RLS 光伝送` | 同上 | 同上 |
| `WaveLogic とは` | コヒーレント技術の名前を聞いた人 | 一般名（コヒーレント光伝送）と対応させる |
| `トランスポンダ マックスポンダ 違い` | 用語の対応関係が分からない | **用語対応表**を作る |
| `ROADM WSS 違い` | 同上 | 同上 |
| `OTN ODU OTU 違い` | 階層構造が分からない | 階層図を1枚描く |

> **⚠️ 型番をタイトルの主語にしない。**
> ✗ `Ciena 6500 完全ガイド`（ベンダー公式と誤認される。商標リスク）
> ○ `波長を1本足すときに確認したこと（Ciena 6500の例）`

## 入口② アラーム・エラー文言（完全一致・最強の入口）

**現場ではアラーム文字列をそのままコピペして検索する。** かつ完全一致クエリはAI Overviewsが出にくい。

| クエリ例 | 記事側の対応 |
|---|---|
| `Pre-FEC Signal Degrade 原因` | **アラーム文字列をH2見出しにそのまま入れる**。前後に日本語の説明 |
| `Pre-FEC Signal Fail` | 同上 |
| `pre-FEC BER 上昇 原因` | 「閾値を超えると何が起きるか」を段階で説明 |
| `OSNR margin 足りない` / `OSNRマージン 不足` | 確認手順を**番号付きリスト**にする（AIが引用しやすい） |
| `LOS アラーム 光レベル` | 「何を測って、いくつなら何を疑うか」を**表**にする |
| `LOF アラーム 光伝送` | 同上 |
| `OTU2 SM-BDI` / `ODU AIS` などOTNアラーム略号 | 略号 → 正式名 → 意味 → 現場での読み方、の**4段**で書く |
| `Q factor 光伝送 いくつ` | 数値の目安と、その根拠 |

**実装ルール**:

- [ ] アラーム文字列を**英語の原文のまま**書く（現場ではコピペされるため。翻訳しない）
- [ ] コードブロックだけでなく、**本文中にも1回は生テキストで**書く
- [ ] 「このアラームが出たときに**最初に**見るもの」を必ず1つ明示する

> **⚠️ 守秘義務**: アラーム文字列は**公開仕様・公開資料に出てくる一般的な文字列**を使い、自分でタイプし直す。
> **自社/前職のログのスクリーンショットは絶対に使わない。**

## 記事1本あたりの実装チェックリスト（+20分）

- [ ] タイトルに**入口①〜③のいずれか1つ**が入っている（2つ以上入れない）
- [ ] H2の少なくとも2つが**質問形**（例: `OSNRが足りないと言われたら何を見るか`）
- [ ] 略号は初出で **3表記そろえる**: `OSNR（Optical Signal-to-Noise Ratio、光信号対雑音比）`
      → 日本語検索・英語検索・略号検索の3つを同時に取る
- [ ] 数値は**必ず表にする**（AI引用されやすい）
- [ ] 冒頭にTL;DR（結論3行）
- [ ] 「主張 → 根拠（数値・出典）」の順で書く
- [ ] 記事末尾に**関連する自記事へのリンクを2本**
- [ ] 公開前に、狙ったクエリを**シークレットウィンドウで実際に検索**して、上位に何があるか見る（3分）
