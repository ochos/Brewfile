この記事は、**光伝送の担当になったばかりで、社内に体系的な資料がなく、ベンダー資料は分厚すぎて読めない1〜3年目**に向けて書いています。

扱うのは OSNR ひとつだけです。ただし「OSNR とは光信号対雑音比のことです」で終わらせず、**なぜ現場が最初にこの数字を見るのか**、**足りないと言われたときに何を確認するのか**まで書きます。

## 1. TL;DR

- 日本では、どのキャリアも**借りたダークファイバの上に**ネットワークを作ります。**OSNR は設計して満たすものではなく、借りた線路が決めた枠の中でやりくりするもの**です。だから最初にここを見ます
- OSNR は「信号のパワー」と「**基準帯域 0.1nm の中に入る雑音のパワー**」の比。分母の幅を決めて初めて数字になります
- 増幅器は信号と雑音を同時に持ち上げるので、**利得を上げても OSNR は良くなりません**。決めるのはアンプ**入力**パワーと NF です
- 「足りない」と言われたら、**「全波長か特定波長か」「いつからか」「測定値そのものは正しいか」**——**確認がタダな3つ**を潰してから実測に入ります

## 2. なぜ OSNR を最初に見るのか

英語で書かれた光伝送の解説を読むと、たいてい**自分たちで敷いたファイバに、設計したとおりの伝送を載せる**前提で話が進みます。損失は設計値、ファイバの種別は選べるもの、という世界です。

日本の現場はそうではありません。

**どのキャリアも、NTT のダークファイバを借りなければネットワークを作れません。** 区間の長さも、経路も、途中の接続点の数も、こちらでは決められない。**物理条件が先にあって、設計がそれに従属します。**

これが効いてきます。

- 借りられる区間には**古い設備が多く、損失が高いものが少なくありません**
- スパン損失が大きいということは、それを補うために**必要な利得が大きい**ということです
- §4 で見るとおり、増幅器は利得を出すぶんだけ雑音（ASE）を足します。**損失が高い区間ほど、OSNR は削られます**
- さらに区間によっては、**ファイバの種別すら選べません。** DWDM に向かない特性のまま使うしかない経路があります

つまり、こういうことです。

:::message
**OSNR は「設計して満たすもの」ではなく、「借りた線路が決めた枠の中で、やりくりするもの」です。**
:::

自社資産のファイバなら、OSNR が足りなければ設計を変えられます。中継点を増やす、経路を変える、ファイバを張り替える。日本の現場では、その多くが選択肢に入りません。**与えられた物理条件のもとで、その回線が成立するかどうか**——それを判定する数字が OSNR です。

だから設計のときも、障害のときも、最初にここを見ます。ここが足りないなら、変調方式を落とすか、波長数を減らすか、経路そのものを諦めるか、いずれにせよ**話の前提が変わる**からです。逆にここに余裕があるなら、多くの問題は他の場所にあります。

## 3. OSNR は何と何を比べているのか

「信号と雑音の比」だけでは、実は数字が決まりません。**雑音は帯域を広く取ればいくらでも増える**からです。10 GHz 分を数えるか 100 GHz 分を数えるかで、同じリンクの同じ雑音が 10 倍違って見えます。

そこで OSNR は、分母の数え方をあらかじめ固定します。慣習的に使われるのが **0.1 nm 幅**という基準帯域です。

$$
\mathrm{OSNR} = \frac{P_{\text{signal}}}{P_{\text{ASE}}\ (\text{基準帯域 }0.1\,\mathrm{nm}\ \text{内})}
$$

| 記号 | 意味 |
|---|---|
| $P_{\text{signal}}$ | チャネルの信号パワー |
| $P_{\text{ASE}}$ | 基準帯域内に入る自然放出光（雑音）のパワー |
| 基準帯域 | 雑音を数える幅。ここでは 0.1 nm |

:::message
**「OSNR は 0.1nm 換算で」という但し書きが必ず付くのはこのためです。** 基準帯域が違えば数字も変わるので、値だけを比べても意味がありません。測定器の設定と、設計書がどの帯域で計算しているかを合わせてください。
:::

### 0.1 nm は何 GHz なのか

雑音を扱うときは、波長（nm）より周波数（GHz）のほうが計算しやすい場面が多くあります。換算は定義から出ます。

$$
\nu = \frac{c}{\lambda} \;\Longrightarrow\; \left|\frac{d\nu}{d\lambda}\right| = \frac{c}{\lambda^{2}} \;\Longrightarrow\; \Delta\nu \simeq \frac{c\,\Delta\lambda}{\lambda^{2}}
$$

| 記号 | 意味 |
|---|---|
| $\nu$ | 光周波数 |
| $\lambda$ | 波長（ここでは 1550 nm） |
| $c$ | 光速 |
| $\Delta\lambda,\ \Delta\nu$ | 波長幅とそれに対応する周波数幅 |

λ = 1550 nm、Δλ = 0.1 nm を入れると **Δν ≈ 12.48 GHz**。同じ式を逆向きに使えば、50 GHz グリッドが 1550 nm 付近で**約 0.40 nm 間隔**になることも出ます。グリッドの数字が nm と GHz の両方で語られるのは、この一本の式でつながっているからです。

λ² が分母にあるので、**同じ 0.1 nm でも波長が違えば GHz 値は変わります**。

ここまでで OSNR が何を比べた数字かを見ました。次は、その比がなぜ悪くなるのかです。

## 4. なぜ劣化するのか

OSNR が落ちる理由は、突き詰めると**雑音を足す装置が経路上にある**ことです。代表が光増幅器です。

光増幅器は入ってきた光を増やしますが、同時に**自然放出光（ASE）を自分で作り出して足します**。そして増幅は、信号と雑音を**一緒に**持ち上げます。後から何倍にしても比は変わりません。

つまり OSNR を決めているのは、**増幅器の入力側で信号がどれだけ残っていたか**と、**その増幅器がどれだけ雑音を足す性質か（NF）**の2つだけです。この一点が、後の §7 のつまずきに直結します。

### 多段中継で積み上がる

区間ごとに損失を増幅で補償する構成では、**信号レベルは各区間で元に戻されるのに、雑音は戻らず足され続けます**。雑音パワーが足し算で積み上がるということは、比の逆数が足し算になるということです。

$$
\frac{1}{\mathrm{OSNR}_{\text{total}}} = \sum_{i} \frac{1}{\mathrm{OSNR}_{i}}
$$

（各区間の雑音が独立に加算され、信号レベルが各区間で同じに戻されるという理想化のもとでの関係です。実装上の細かい差は無視しています。）

読み取ってほしいのは値ではなく**形**です。逆数の和なので、**一番悪い区間が全体を支配します**。また同じ区間を N 個並べれば全体は 10·log₁₀(N) dB ぶん悪くなり、区間数が倍で約 3 dB、8 倍で約 9 dB です。

:::message alert
裏を返すと、**1区間だけが極端に悪いとき、他をどれだけ良くしても全体はほとんど改善しません。** 「全体的に少しずつ悪い」のか「1か所だけ悪い」のかで、打つ手が変わります。
:::

## 5. 設計値と実測値の差 — マージン

設計時に計算した OSNR と、現地で測った値は一致しません。**ズレることを前提に設計します。**

ズレの出どころは、大きく4つに分けられます。

### (1) 借りた区間の実際の損失が、想定と違う

§2 のとおり、区間の物理条件はこちらでは決められません。台帳上の距離や公称の損失と、実際に測った値が違うことがあります。**設計の入力そのものがズレていた**という形なので、影響が最も直接的です。

### (2) 接続点の数と質

融着点、コネクタ、途中の設備。**経路が長いほど、また古いほど、数えきれていない接続点が増えます。** 1か所あたりは小さくても、積み上がります。

### (3) 経年と環境

敷設後の年数、温度、周辺工事。**同じ区間でも、測る時期によって動きます。**

### (4) 測定条件そのもの

どこで測ったか、どの分解能帯域で測ったか。**§3 で見たとおり、OSNR は分母の幅を決めて初めて数字になります。** 測定器の設定が違えば、同じリンクでも違う数字が出ます。**「値が変わった」のか「測り方が変わった」のかを最初に分けないと、存在しない問題を追いかけることになります。**

### マージンは何のために取るのか

上の(1)〜(3)は、**設計時点では正確に知りようがありません。** マージンは「安全のため」という漠然としたものではなく、**知りようがない量を、知らないまま設計を成立させるための幅**です。

だから、何を見込んだマージンなのかを分けて持つ必要があります。経年で今後さらに劣化する分、測定のばらつきの分、将来の経路変更の分——**一緒くたにすると、削っていいマージンと削ってはいけないマージンの区別がつかなくなります。**

## 6. 足りないと言われたときに確認する順序

:::message alert
**以下は、この記事の §3〜§5 で説明した原理から組み立てた順序です。** 現場での実際の優先順位は、設備の構成や運用によって変わります。筆者の環境での順序は末尾に補足します。
:::

順序の原則は2つです。**情報を取るコストが低いものを先に**、そして**分岐を大きく減らすものを先に**。

### 1. 全波長の問題か、特定の波長だけか

**最初にここを分けます。** 分岐が最も大きく、そして管理画面で見えるので確認コストがほぼゼロだからです。

全波長なら共通部分（区間、増幅器、経路）の問題。特定波長だけなら、その波長の送受信側か、波長固有の要因。**この先の手順が丸ごと変わります。**

### 2. いつからそうなのか

**変化点があるかを見ます。** 直前に工事、切替、経路変更がなかったか。

「ずっと悪かった」なら設計の問題、「ある時点から悪くなった」なら変化の問題です。**これも確認コストが低く、原因の範囲を大きく絞ります。**

### 3. 測定値そのものを疑う

測定点、測定器、分解能帯域。**§5 の (4) です。**

順番として3番目に置いているのは、**ここで「実は問題がない」と分かることがあり、しかも確認がタダだから**です。機器を触る前に潰します。

### 4. 区間ごとの内訳を見て、悪い区間を1つに絞る

§4 で見たとおり、多段では**一番悪い1区間が全体を支配します**。全体の値だけを見ていても打つ手は決まりません。

**「全体的に少しずつ悪い」のか「1か所だけ悪い」のか。** ここで分かれます。前者なら設計全体の見直し、後者ならその1区間の話です。

### 5. その区間の入力パワーを見る

§4 の結論を使います。**OSNR を決めるのは増幅器の入力パワーと NF の2つだけ**でした。入力パワーが想定より低ければ、その手前で信号が失われています。

### 6. スパン損失を、実測値と設計値で比べる

入力パワーが低い原因のほとんどはここです。**§2 のとおり借りた線路なので、ここは動きます。** §5 の (1)〜(3) が効いてくる場所です。

### 7. 増幅器の動作点を確認する

利得設定、パッド、動作範囲。**NF は動作点によって変わります。** 設計時に想定した動作点から外れていないかを見ます。

### 8. 波長固有の要因（1 で「特定波長だけ」だった場合）

送信側の出力、受信側の感度、波長の設定、フィルタの通過帯域とのズレ。

### 9. 非線形の影響を疑う

**最後に置いています。** 切り分けの手間が最も重く、かつ他の可能性を潰してからでないと判断できないからです。投入パワーが過大でないか、分散の小さい区間を通っていないか。

---

### この順序が「何の順」か

**確認コストの低い順 × 分岐を減らす効果の大きい順**です。発生頻度の順ではありません。

理由は、**頻度順に並べると、たまたま今回が稀なケースだったときに一番遠回りになる**からです。1〜3 は情報を取るのがほぼタダで、しかもそれぞれが可能性を半分に切ります。ここを飛ばして 5〜7 の実測に入ると、確認していない前提の上で作業することになります。

### やりがちな誤った順序

**いきなり増幅器の利得を上げる。** これが最も多い誤りで、しかも改善しません。理由は §7 の (1) で説明します。

**測定値を疑わずに機器交換へ進む。** 手順 3 を飛ばすと、存在しない問題のために設備を触ることになります。

**全波長か特定波長かを分けずに個別対処する。** 共通部分の問題を、波長ごとに何度も追いかけることになります。

## 7. つまずきポイント

### (1) 「利得を上げれば OSNR が良くなる」ではない

実務でよく見かける誤りが、1スパンの OSNR をこう書くものです。

```
OSNR = P_TX + G − L − NF     ← 誤り
```

一見それらしく見えますが、**利得 G は OSNR の式に現れません。** §4 のとおり G は損失を補償するだけで、SN 比を改善しないからです。正しくは、アンプ**入力**パワーと NF で決まります。

```
OSNR = P_in − NF + 58        （P_in はアンプ入力パワー [dBm]）
     = P_TX − L − NF + 58    （単スパン）
```

この誤りが厄介なのは、**健全なリンクを不良と誤判定する**点です。

| | 式 | 結果 |
|---|---|---|
| 誤 | P_TX + G − L − NF | **−5.0** |
| 正 | P_TX − L − NF + 58 | **31.0 dB** |
| | 差 | **36 dB** |

（P_TX = 0 dBm、スパン損失 L = 22 dB、利得 G = 22 dB、NF = 5 dB の場合）

損失をきっちり補償した設計、つまり G = L のときに G と L が相殺してしまうため、**設計が正しいときほど大きく外れます**。

### (2) 「+58」はマジックナンバーではない

上の式の 58 は、覚えるべき定数ではなく**計算できる値**です。基準帯域 0.1 nm に入る量子雑音の下限が h·ν·B_ref で、dBm にすると約 −58 dBm。式の中で符号が反転して「+58」になっています。

| 記号 | 意味 | 値 |
|---|---|---|
| h | プランク定数 | 6.62607015 × 10⁻³⁴ J·s（SI 定義値） |
| ν | 光周波数 | c/λ = 193.41 THz（λ = 1550 nm） |
| B_ref | 基準帯域 | Δν = c·Δλ/λ² = 12.478 GHz（Δλ = 0.1 nm） |

手元で確認できます。

```python
import math
h, c, lam, dlam = 6.62607015e-34, 2.99792458e8, 1550e-9, 0.1e-9
nu = c / lam
B  = c * dlam / lam**2             # 0.1nm → 12.478 GHz
print(10 * math.log10(h * nu * B * 1e3))   # → -57.96 dBm
```

:::message
**この 58 は λ と基準帯域に依存します。** 別の波長や別の基準帯域を使うなら、同じ式に入れ直して自分で出し直してください。定数として暗記すると、条件が変わったときに気づけません。
:::

### (3) dB と dBm を足す

定義に戻れば迷いません。

- **dB は比**（無次元）。**dBm は 1 mW を基準にした絶対値**
- dBm − dBm = **dB**（差は比になる）
- dBm + dB = **dBm**（絶対値に利得・損失を足す）
- **dBm + dBm は意味を持たない**

「+58」の式も、この規則で読めます。P_TX（dBm）から L と NF（dB）を引いて、−58 dBm を割る＝引く、で最後に残るのは **dB**、つまり比です。**OSNR の単位が dB であって dBm でないこと**自体が、検算のチェックポイントになります。

Q13: dB / dBm 以外に混同しやすいもの（基準帯域の違いによる値のズレなど）
Q14: コヒーレント伝送が主流になって OSNR の意味・扱いが変わったと感じる点
     → ここは断定できる範囲だけ。曖昧なら節ごと落としてよい

## 8. まとめ

- OSNR は、**分母を「基準帯域 0.1 nm の中」と決めて初めて数字になります**。値を比べる前に帯域の前提を揃えてください
- **増幅器は SN 比を改善しません。** OSNR を決めるのはアンプ**入力**パワーと NF であり、利得 G は式に現れません
- 多段では雑音が**逆数の和**で積み上がり、一番悪い区間が全体を支配します
- 「+58」は暗記する定数ではなく、h·ν·B_ref から**その場で計算できる値**です

数字を覚えるのではなく、**どの定義から出てきた数字かを追えるようにしておく**こと。前提が変わったときに気づけるのは、それだけです。
