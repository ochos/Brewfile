## 0. 結論

| 段階 | 主戦場 | 商品 | 価格 | 集客 |
|---|---|---|---|---|
| **M1** 月商1,000円 | **Zenn Books（デジタル買い切り）** | 500円の技術書1冊 | 500円 | Zenn / Qiita 記事 |
| **M2** 月商1万円 | **Chrome 拡張（買い切り or 小額サブスク）** | 拡張1〜3本 | 500円/月 or 1,000円買い切り | Chrome Web Store 内検索 + Zenn 読者 |
| **M3** 月商10万円 | 上記の複数本展開 + サブスク化 | 拡張5〜10本 / SaaS 1本 | 500〜1,000円/月 | SEO資産 + メルマガ + 英語圏 |

**受託（業務自動化の請負）は「補給線」として温存し、常時は走らせない。**

## 1. なぜこの結論になったか — 調査結果の突き合わせ

### 1-1. 各エージェントの推薦は一致しなかった

| 調査 | 推した先 |
|---|---|
| 市場調査（01） | **第1位: 受託**（月1,000円到達が最速・最確実）、第2位: Chrome拡張、第3位: デジタル買い切り |
| 集客調査（03） | Zenn / Qiita 記事を主力に。「月商1,000円 = 有効閲覧200〜400回で届く」 |
| 技術調査（04） | Cloudflare 一式で Web サービス。ただし「**ボトルネックはインフラではなく集客**」 |
| 法務税務（02） | 月1,000円段階は **BOOTH / note に寄生**。Stripe 直販は月10万円から |

### 1-2. 受託を第1位から降ろした理由

市場調査は受託を第1位に置いたが、**この調査を起動した時点で「技術レベル＝少し書ける」というヒアリング結果がまだ無かった**。この条件を入れると評価が変わる。

| 論点 | 受託が抱える問題 |
|---|---|
| **納期責任** | 発注者に対して契約上の債務を負う。「少し書ける」水準で、Claude Code の出力を完全には検証できない状態で、他人の業務に使われる成果物の納期を握るのはリスクが非対称。動かなければ返金・炎上・評価毀損まで一直線 |
| **週5〜10時間との相性** | 本業が炎上した週に、発注者の納期は待ってくれない。時間の融通が効かない唯一のモデル |
| **就業規則** | 「役務提供による報酬」は副業禁止規定に最も明確に抵触しやすい形態。デジタル商品販売より会社に説明しづらい |
| **天井** | 労働集約なので月10万円で頭打ち（市場調査も明記） |

→ **受託は「最速で1,000円に届く」が「最も早く事故る」。** 初手には置かない。

ただし受託の利点（顧客課題の一次情報が手に入る＝作るネタが見つかる）は本物なので、**捨てずに「補給線」として温存**する。発動条件は §4 に定義。

### 1-3. Zenn Books を M1 に置いた決定的な理由

**集客チャネルと商品が同一である。** これが週5〜10時間という制約下で決定的に効く。

- 集客調査の結論は「Zenn / Qiita 記事が最短」
- 市場調査の第3位は「デジタル買い切り販売」で、実例が **Zenn Books で500円本を5冊（＝2,500円）売った無名アカウント**
- つまり **記事を書く時間が、そのまま集客工数であり、かつ商品制作工数でもある**

他の組み合わせ（例: Chrome拡張 × Zenn記事）では、「拡張を作る時間」と「記事を書く時間」が別々に必要になる。週5〜10時間ではこの二重負担が最初の脱落要因になる。

さらに制約との適合:

| 制約 | Zenn Books の適合 |
|---|---|
| 週5〜10時間 | ◎ 記事執筆が集客と商品を兼ねる |
| 少し書ける | ◎ 「動くコード」ではなく「調べた過程」が商品。品質責任が軽い |
| 実名OK・顔出しNG | ◎ テキストのみ。顔出し要素ゼロ |
| 月1,000円以内の固定費 | ◎ **固定費ゼロ**（Zenn は販売手数料のみ） |
| やめるコストが低いか | ◎ 在庫なし・契約なし・審査なし。失うのは時間だけ |

**下振れも直視する**: 最大のリスクは「出したが1冊も売れない」。市場調査は Gumroad で22商品出して「ほぼ売れたことがない」証言を記録している。**商品を作る時間より告知に使う時間のほうが重要**、という認識がないと失敗する。→ 90日計画では告知工数を明示的に確保する。

### 1-4. M2 を Chrome 拡張にした理由

M1 で「文章は書けるが、動くものを売った実績はない」状態になる。次はそこを埋める。

- 初期費用 **$5（約750円）一回きり**。全候補中で最も資本効率が良い
- **Chrome Web Store が集客を内蔵**している。個人開発最大の壁「見つけてもらう」をストア内検索が肩代わりする
- Manifest V3 / content script / service worker という定型構造でコード量が小さく、**「少し書ける」水準でも Claude Code の出力を読み切れる**
- 「1本 × 課金10人 × 500円 = 5,000円、10本で5万円」という**打席数で勝つ設計**。一発当てる必要がない

**下振れ**: 1本目が全く使われない確率は高い（実例の開発者は17〜20本作っている）。**10本作る覚悟が前提**で、1本目で諦めると何も残らない。

### 1-5. 明示的に捨てるもの

| 捨てるもの | 理由 |
|---|---|
| **アフィリエイト主軸** | 日本アフィリエイト協議会2025調査で **52.5%が月1,000円未満、38.4%が収入ゼロ**。期待値が全候補中最低。集客の副産物としてのみ使う |
| **マイクロSaaS を初手に** | $1K MRR 到達は中央値12〜18ヶ月、70%が月$1,000未満。M1に対して回収期間が長すぎる。M3で再検討 |
| **iOS アプリ** | Apple Developer $99/年が初期費用の制約を超える |
| **物理物販** | 在庫・発送が週5〜10時間と衝突。Claude Code の優位もゼロ |
| **汎用AIラッパー** | 基盤モデル提供者に内製されて消える定番の地雷。App Store も飽和カテゴリとして審査を厳格化 |
| **AI記事の量産SEO** | Google のスパムポリシー（scaled content abuse）の直撃対象。最も高確率で無に帰す |
| **動画チャネル（YouTube/TikTok）** | 顔出しNG。かつ週5〜8時間を単独で食う |

## 2. 収益モデルの積み上げ設計

```
M1: 月商 1,000円
    Zenn Books 500円 × 2冊/月
    └ 必要な有効閲覧: 約400PV（実測転換率 約1.25%）

M2: 月商 10,000円
    Zenn Books 500円 × 4冊/月    =  2,000円
    Chrome拡張 500円/月 × 16人   =  8,000円
    └ 拡張は解約されない限り翌月も入る（ここで初めてストック収入になる）

M3: 月商 100,000円
    Chrome拡張 500円/月 × 150人  = 75,000円（5〜10本の合計）
    デジタル商品                  = 15,000円
    メルマガ経由の高単価商品       = 10,000円
```

**M1→M2 の質的な変化**: フロー収入（毎月ゼロから売る）から**ストック収入**（先月の顧客が今月も払う）への移行。ここが本当の分岐点であり、月1,000円という金額そのものには意味がない。

## 3. 決済・法務の段階設計（研究02の結論を採用）

**最初から Stripe を入れない。** 審査・特商法表記・税務が同時に重くなり、月1,000円の段階では割に合わない。

| 段階 | 決済 | 特商法表記 | インボイス | 確定申告 |
|---|---|---|---|---|
| M1 | **Zenn / BOOTH に寄生** | プラットフォームが代行 → **自宅住所の公開が不要** | 不要 | 所得20万円以下なら所得税は不要。**ただし住民税の申告は必要** |
| M2 | + もしもアフィリエイト | 同上 | 不要（B2C中心なら免税事業者のまま） | 同上（20万円を超えたら申告） |
| M3 | Stripe 直販 + 越境は MoR | **自前で必要** → バーチャルオフィス等の対策 | 要検討 | 開業届・青色申告を検討 |

**M1 でプラットフォームに寄生する最大の理由は手数料ではなく、「実名OK・顔出しNG」の人が自宅住所を晒さずに済むこと。** Stripe 直販に切り替えた瞬間、特商法11条により住所・電話番号の表示義務が発生する。

## 4. 受託の発動条件（補給線）

以下のいずれかに該当したときだけ、受託を1件受ける。常時は走らせない。

1. **90日経っても M1（月1,000円）に届かない** → 現金と顧客課題の一次情報を同時に取りに行く
2. **書くネタが枯れた** → 実案件が最良のネタ源
3. **本業が安定していて、時間に余裕のある月がある**

受けるときの**ハードルール**（破らない）:

- 納期は**2週間以上**のものだけ。短納期は受けない
- 要件が**1画面で書ける**ものだけ。「相談しながら決めましょう」は受けない
- 単価5,000〜30,000円の小口のみ。大型案件は受けない
- **同時に2件受けない**
- スクレイピング案件は、対象サイトの規約確認を発注者と**文書で握る**

## 5. 中止・撤退の基準

「なんとなく続けている」を防ぐため、先に決めておく。

| 時点 | 判定 | 未達なら |
|---|---|---|
| Day 30 | 記事2本公開 + 本1冊公開済み | 公開できていない → 原因は「作りすぎ」。スコープを半分にする |
| Day 60 | **売上1円以上**（金額不問） | 1円も売れていない → 商品ではなく**告知量**を疑う。§7-3のアンチパターン該当を確認 |
| Day 90 | 月商1,000円 | 未達 → 受託を1件発動して現金と課題情報を取る。撤退はしない |
| Day 180 | 月商1万円 | 未達 → **モデルを変える**。Zenn Books の売上が伸びないなら、それは市場の答え |

**撤退条件**: 固定費が月1,000円を超え、かつ3ヶ月連続で売上ゼロ。このときは一度全部止める。

## 6. この戦略が間違っている可能性

正直に書いておく。

1. **Zenn Books の実例は n=1**。「2,000PV → 5冊」という転換率は単一事例からの外挿であり、母集団の中央値ではない。**売れない可能性のほうが高い**と見ておくべき
2. **「集客と商品が同一」は諸刃**。記事が読まれなければ商品も売れず、失敗の原因が切り分けられない
3. **Chrome 拡張は Manifest 仕様変更のリスク**を恒常的に負う。Google の一存で作り直しが発生する
4. **受託を降ろした判断は保守的すぎるかもしれない**。「少し書ける」水準でも、小口の GAS 案件なら Claude Code で十分完走できる可能性はある。Day 90 の判定で再考する
